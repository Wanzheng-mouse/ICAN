# 第四阶段前端完成说明

## 1. 阶段目标

第四阶段完成从“已保存场景”到“真实仿真运行”的前端闭环。运行空间不再使用固定 `mock` ID，也不在页面打开后静默创建运行；仿真创建、状态查询、开始、暂停、停止、异常注入、实时数据和断线恢复均以真实 `simulationId` 为主线。

## 2. 已完成内容

### 场景编辑器创建仿真

- 用户点击“进入仿真”时，编辑器先调用创建仿真接口。
- 默认按第四阶段验收规模创建 10 台 AGV、20 个订单。
- 创建成功后把 `projectId`、`scenarioId`、`simulationId` 写入全局上下文。
- 跳转 URL 明确携带三个业务 ID，刷新后仍能定位同一运行。
- 创建失败时停留在编辑器并显示可理解的错误，不进入无效运行页面。

### 仿真运行读取与控制

- 仿真页按“URL 优先、Store 兜底”读取 `simulationId`。
- 缺少 ID 时显示引导状态，返回场景编辑器创建仿真，不再回退到固定 `mock` ID。
- 加载失败、运行不存在、后端未启动分别显示错误和重试入口。
- 开始、暂停、停止均等待后端成功响应后再更新页面状态，失败时不会制造前后端状态不一致。
- 停止成功后重置本地动画、时间和运行快照。
- 异常注入先写入后端，成功后再触发本地三维表现和事件提示。

### WebSocket 实时数据

- 新增 `useSimulationStream`，连接 `/api/v1/simulations/{simulationId}/stream`。
- 严格识别 `simulation_tick` 数据结构，拒绝不完整或错误消息。
- 实时更新仿真时间、任务完成数、完成率、处理时长、拥堵、能耗、设备电量和设备状态。
- 后端事件流和 REST 事件历史会去重合并到页面事件记录。
- 三维设备状态以实时流为准；当前后端未发送坐标时，位置动画继续使用统一仓库引擎，电量和运行状态使用后端数据覆盖。
- 断线期间暂停三维动画，保留最后快照并显示重连状态。
- 自动重连成功后重新读取运行详情、设备和事件，恢复页面一致性。
- 支持用户手动立即重连。

### 仿真运行子页面

左侧运行菜单不再全部重复显示同一个总览页面：

| 页面 | 已实现内容 |
|---|---|
| 总览 | KPI、三维数字孪生、控制栏、AGV 详情、事件和场景状态 |
| 仿真空间 | 独立 `/simulation/live` 地址，保留全部三维运行能力 |
| 任务管理 | 任务类型、优先级、分配设备、状态、进度和 ETA |
| 设备管理 | AGV 电量/载荷/任务、工作站队列、充电桩占用和等待队列 |
| 订单管理 | 订单、SKU、包装、数量、重量、生命周期状态和当前位置 |
| 智能体 | 智能体负载、成功率、延迟、职责和运行状态 |
| 告警中心 | 告警事件、严重程度、来源、时间及异常注入入口 |
| 数据看板 | 完成率、处理时长、利用率、能耗、拥堵和异常数量 |
| 设置 | 本次运行规模、动画速度、最后实时数据和数据优先级说明 |

所有子页面切换时保留 URL 查询参数，避免丢失项目、场景和仿真上下文。

### API 和类型契约

- 补充 `SimulationTickRead`、`SimulationRobotRead`、`SimulationEventRead`、`SimulationAgentRead` 和运行状态类型。
- 控制与异常接口返回更新后的 `SimulationRead`，TanStack Query 同步更新运行缓存。
- 设备和事件接口增加后端 DTO 到页面模型的转换，不再把不匹配的后端结构直接断言成前端类型。
- 所有仿真 Query 在缺少 ID 时保持禁用，不发送 `mock` 请求。
- Mock 模式保留完整创建、控制、异常和实时 tick 行为，用于离线演示和测试。

## 3. 当前使用的接口

| 能力 | 接口 |
|---|---|
| 创建仿真 | `POST /api/v1/simulations` |
| 查询仿真 | `GET /api/v1/simulations/{id}` |
| 控制仿真 | `POST /api/v1/simulations/{id}/control` |
| 注入异常 | `POST /api/v1/simulations/{id}/anomalies` |
| 设备/智能体 | `GET /api/v1/simulations/{id}/agents` |
| 事件历史 | `GET /api/v1/simulations/{id}/events` |
| 实时数据 | `WS /api/v1/simulations/{id}/stream` |

## 5. 人工联调验收

1. 启动后端和前端，从项目中心打开场景编辑器。
2. 保存场景并点击“进入仿真”，确认 URL 中包含真实 `simulationId`。
3. 点击开始，确认后端状态变为 `running`，WebSocket 时间和指标持续更新。
4. 切换任务、设备、订单、智能体、告警和数据看板，确认 URL 参数没有丢失。
5. 暂停仿真，确认指标和三维动画停止；再次开始后继续运行。
6. 注入道路封锁、低电量、订单激增或工位停机，确认事件与指标同步变化。
7. 临时停止后端，确认页面进入重连状态且三维动画冻结；恢复后端，确认页面自动同步。
8. 点击停止并重置，确认运行状态、动画和时间回到待运行状态。

## 6. 后端数据边界说明

当前 WebSocket tick 已提供机器人 ID、状态、电量、任务汇总、事件和指标，但没有提供机器人的实时坐标、路径和货物位置。因此前端已经完成实时状态闭环，三维位置仍由本地统一仿真引擎生成。若第五/第六阶段要求服务器完全主导三维轨迹，后端需要在 tick 中增加机器人坐标、路径、任务 ID、载货状态和货物位置字段，前端实时流层已经预留接入位置。
