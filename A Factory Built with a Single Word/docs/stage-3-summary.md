# 第三阶段前端完成说明

## 1. 阶段目标

第三阶段将场景编辑器从静态原型升级为可与后端场景数据真实联动的工作区。编辑结果以 `Scenario.data` 为唯一持久化结构，刷新页面后能够按项目和场景 ID 恢复，保存时使用版本号进行并发控制。

## 2. 已完成内容

### 场景上下文与数据加载

- 优先读取 URL 中的 `projectId` 和 `scenarioId`，缺失时再使用全局项目上下文。
- 首次打开、刷新和手动重新加载均从场景接口读取真实数据，不再展示伪造的默认组件。
- 服务端返回的项目归属与 URL 不一致时，以服务端数据为准并修正全局上下文。
- 缺少场景 ID、场景不存在、无权限、网络失败分别显示明确的空状态或错误状态。

### 场景编辑能力

- 组件库支持搜索、分类添加和自定义组件。
- 支持选择、拖动、删除、旋转、六方向对齐、撤销和重做。
- 拖动坐标按照缩放比例换算，并限制在画布边界内。
- 属性面板可编辑名称、坐标、尺寸、旋转角度及货架容量、AGV 初始电量等扩展属性。
- 画布宽度、高度和坐标比例可编辑，并随场景数据一起保存。
- 组件统计、占用面积、可通行率和本次编辑日志均由当前画布实时计算。

### 校验、保存与并发处理

- 本地即时校验组件 ID、名称、尺寸、越界和组件重叠。
- 编辑停止后调用后端校验接口复核，问题组件在画布上高亮，可从校验面板直接定位。
- 保存携带 `expected_version`，区分保存中、已保存、未保存、校验失败、版本冲突和普通错误。
- 发生 409 版本冲突时保留本地内容，提供查看版本历史或放弃本地修改并加载最新版本的处理入口。
- 浏览器刷新或关闭前存在未保存修改时给出离开提示。
- 只有保存完成后才能进入仿真，避免仿真读取旧场景。

### 自动布局与版本历史

- 自动布局调用真实接口，并保留当前画布尺寸；结果先加载到本地，用户确认保存后才持久化。
- 版本抽屉展示版本号、名称、组件数和创建时间。
- 历史快照可载入当前编辑器，保存后生成新版本，不直接覆盖历史数据。
- Mock 模式下也保存完整版本快照，并通过深拷贝避免当前编辑污染历史版本。

### 权限与交互

- `viewer` 等无编辑权限角色进入只读模式，可查看属性、校验结果和版本历史，但不能修改或保存。
- 支持 `Ctrl/Cmd + S` 保存、`Ctrl/Cmd + Z` 撤销、`Ctrl/Cmd + Y` 重做、`Delete` 删除和 `Esc` 取消选择。
- 输入框、下拉框等表单获得焦点时不会误触编辑器快捷键。
- 页面覆盖桌面、窄屏和移动宽度下的响应式布局。

## 3. 前后端接口闭环

编辑器当前使用以下场景接口：

| 能力 | 接口 | 前端行为 |
|---|---|---|
| 读取场景 | `GET /api/v1/scenarios/{id}` | 初始化、刷新、冲突恢复 |
| 校验场景 | `POST /api/v1/scenarios/{id}/validate` | 防抖复核、手动校验、保存前校验 |
| 保存场景 | `PUT /api/v1/scenarios/{id}` | 携带 `expected_version` 乐观锁保存 |
| 自动布局 | `POST /api/v1/scenarios/{id}/auto-layout` | 生成本地待保存布局 |
| 版本历史 | `GET /api/v1/scenarios/{id}/versions` | 查看和载入历史快照 |

## 4. 验证结果

- TypeScript 类型检查通过。
- ESLint 检查通过，0 错误、0 警告。
- 前端测试共 84 项通过，其中包含场景边界、重叠、重复 ID、Mapper 深拷贝、刷新恢复、自动布局和版本历史测试。
- 生产构建通过后，本阶段可进入前后端联调验收。

## 5. 联调验收步骤

1. 从首页或项目中心创建项目与场景并进入编辑器。
2. 添加、拖动和修改多个组件，确认校验面板能定位越界或重叠问题。
3. 修复问题并保存，确认版本号递增。
4. 刷新浏览器，确认组件、画布和版本与保存前一致。
5. 打开两个浏览器窗口编辑同一场景，先后保存，确认后保存的窗口进入版本冲突状态。
6. 查看版本历史并载入旧快照，再次保存，确认生成新版本。
7. 使用只读账号打开场景，确认所有写操作被禁用。
